# Egrit-Preflight v0.1.0

Last updated: 2026-10-30. First public release.

Egrit-Preflight runs read-only checks on a Linux or macOS host and on a container image for a linux/arm64 (NVIDIA
Jetson) target: Docker and emulation readiness (`doctor`); image architecture, declared versions and listed
attestations, without pulling (`image`); an optional ARM64 smoke test that you must ask for (`smoke`); and a JSON
report with a documented contract (`report`). Standard library only. No account, token or telemetry.

## What this release cannot verify

- Anything on a Jetson: GPU, CUDA, TensorRT, device nodes, drivers, performance. Every such check is
  `REQUIRES_HARDWARE`, and `hardware_verified` is always `false` in every report.
- That a container works on a Jetson. An ARM64 execution under QEMU or on an ARM64 runner is not a Jetson result.
- Attestations. A listed SBOM or provenance is the publisher's declaration: its contents are not read and
  `signature_verified` is always `false`.
- Target records. Their values are declared until replaced by what a device reports. The records in
  `examples/targets/` cite NVIDIA's release pages and the date they were read; they are not read from a device.
- NVIDIA L4T images beyond a registry read. One L4T image was inspected from its registry by digest
  (`docs/l4t-example.md`); nothing from it has run anywhere.
- Docker Desktop, on a Mac or elsewhere. See `docs/verification.md`.

## Verified

Unit tests on Linux and macOS across Python 3.9 to 3.13; a real linux/arm64 container execution under QEMU and on a
native arm64 runner; a clean install of the wheel; a registry read of one NVIDIA L4T image by digest. The runs are
recorded in `docs/verification.md`.

## Security review

Two independent AI reviews, each started with no knowledge of the author's conclusions and unable to edit files. Neither
was a human review.

- 2026-10-26: command construction, container isolation and report contents. No remote code execution, injection or
  consent bypass; twelve smaller findings, each fixed with tests or recorded in `docs/security.md`.
- 2026-10-30: everything changed since, including the new registry lookups and the release workflow. No command or
  script injection; seven findings, all fixed before this release with tests. The most serious: a registry could put
  escape sequences into the reported architecture, which the reader exported; both the tool and the reader now refuse
  such values (report contract rule 12).

## Install

Install the wheel attached to this release with `pip install egrit_preflight-0.1.0-py3-none-any.whl`, or install from
the repository as the README describes. Publishing to PyPI follows separately.
